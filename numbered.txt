48: Our goal is to better understand how language

51: analyze model performance on multi-document
52: question answering, which requires models to find
53: relevant information within an input context and

55: make controlled changes to the length of the input
56: context and the position of the relevant informa-
57: tion and measure changes in task performance.
58: 2.1 Experimental Setup
59: In the multi-document question answering task,
60: the model inputs are (i) a question to answer and
61: (ii) k documents (e.g., passages from Wikipedia),
62: where exactly one of the documents contains the
63: answer to the question and k −1 ‘‘distractor’’
64: documents do not. This task requires the model
65: to access the document that contains the answer
66: within its input context and use it to answer the
67: question. Figure 2 presents an example.
68: We instantiate this task with data from
69: NaturalQuestions-Open (Lee et al., 2019;
70: Kwiatkowski et al., 2019), which contains
71: historical queries issued to the Google search
72: engine, coupled with human-annotated answers
73: extracted from Wikipedia. In particular, we take
74: the 2655 queries where the annotated long answer
75: is a paragraph (as opposed to a list or a table).
76: We use passages (chunks of at most 100 tokens)
77: from Wikipedia as documents within our input
78: contexts. For each of the queries, we need a
79: document that contains the answer and
80: k −1
81: distractor documents that do not contain the
82: answer. To obtain a document that answers the
83: question, we use the Wikipedia paragraph that
84: contains the answer from the NaturalQuestions
85: annotations.
86: To collect k −1 distractor documents that do
87: not contain the answer, we use a retrieval system
88: (Contriever, fine-tuned on MS-MARCO; Izacard
89: et al., 2021) to retrieve the k−1 Wikipedia chunks
90: that are most relevant to the query and do not
91: contain any of the NaturalQuestions-annotated
92: answers.

11: 5 Is More Context Is Always Better?
12: A Case Study With Open-Domain QA
13: Our results indicate that prompting lan-
14: guage models with longer input contexts is a
15: trade-off—providing the language model with
16: more information may help it perform the
17: downstream task, but it also increases the amount
18: of content that the model must reason over, po-
19: tentially decreasing accuracy. Even if a language
20: model can take in 16K tokens, is it actually
21: beneficial to provide 16K tokens of context? The
22: answer to this question is ultimately downstream
23: task-specific since it depends on the marginal
24: value of the added context and the model’s ability
25: to effectively use long input contexts, but we
26: perform a case study with open-domain question
27: answering on NaturalQuestions-Open to better
28: understand this trade-off in existing language
29: models.
30: We use language models in a standard
31: retriever-reader setup. A retrieval system (Con-
32: triever, fine-tuned on MS-MARCO) takes an input
33: query from NaturalQuestions-Open and returns
34: the
35: k documents from Wikipedia with the highest
36: relevance score. To condition language models
37: on these retrieved documents, we simply include
38: them in the prompt. We evaluate retriever recall
39: and reader accuracy (whether any of the annotated
40: answers appear in the predicted output) as a func-
41: tion of the number of retrieved documents

72: 6.1 Long-Context Language Models
73: There is much prior work in designing perfor-
74: mant language models with cheaper scaling than
75: Transformers in the context length. Many lines of
76: work pursue Transformer variants with attention
77: modifications like recurrence (Dai et al., 2019),
78: factorizing attention into computationally less
79: intensive approximations (Beltagy et al., 2020;
80: Zaheer et al., 2020), or low-rank approximations

85: entirely to remove quadratic sequence length com-
